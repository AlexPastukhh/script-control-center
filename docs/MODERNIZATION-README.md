# Fortis / RDG Control Center — кандидат модернизации

**Это рабочая копия, не установленная Windows-версия.** Windows-оригиналы, работающие сервисы Fortis Repo, RDG, updater, watcher не затрагивались.

## Изменения

- В исходный `ControlCenter.cs` добавлена кнопка **«Скрипты…»**, открывающая отдельное окно управления.
- Новый `ScriptCatalog.cs`: регистрация существующих файлов по абсолютному пути, редактирование, удаление регистрации без удаления файла, сохранение каталога в `%LOCALAPPDATA%\FortisRdgControlCenter\scripts\catalog.xml`.
- Поддержаны локальные `.ps1`, `.bat`, `.cmd`, `.py`, `.exe`. Файл и рабочая папка должны существовать на машине Windows.
- Режим **«Внутри центра»** по умолчанию запускает независимый фоновый `Script-Runner.ps1` без консольного окна, собирает stdout/stderr в ограниченный 2 MiB журнал (с сокращением до ~1 MiB) и показывает последние ~90 KiB в GUI. PowerShell-библиотека динамически компилируется на Windows.
- Режим **«Своё окно»** запускает скрипт с обычным окном, но не захватывает его stdout. Интерактивные скрипты следует запускать только в этом режиме.
- Перед запуском требуется подтверждение. GUI не запускает зарегистрированные скрипты автоматически.
- Точный PID и время старта сохраняются для проверки существования процесса после повторного открытия GUI. Для фонового режима остановка передаётся собственному runner через одноразовый token-specific `.stop`; runner вызывает `taskkill /T /F` для дерева созданного им процесса с fallback на прямой PID. Для «Своего окна» останавливается только дерево подтверждённого PID, предварительно проверенного по времени старта. Внешние процессы только по совпадению имени не останавливаются.
- Закрытие Control Center не должно автоматически завершать пользовательские процессы. Четыре штатных подключения и оригинальные Windows-скрипты сохранены. В кандидате убрана только искусственная проверка порядка запуска/остановки Repo 1 и Repo 2; Guard, Docker и установленные запускатели не изменены.

## Исправления UI и регистрации — 01.11.2026

- Сохранение каталога больше не вызывает `File.Replace(temp, catalogPath, null)`: для атомарной замены используется уникальный реальный путь резервной копии. Временный файл удаляется в `finally`; сохраняется до пяти последних резервных копий каталога.
- Интерфейс перестроен: список теперь имеет колонки «Название / Состояние / Режим», правая панель показывает имя, полный путь, рабочую папку, PID/время старта и явный заголовок журнала. Начальные состояния журнала больше не пустые.
- Компоновка сделана через `TableLayoutPanel` и адаптивный `SplitContainer`; начальные размеры применяются после `Shown`. Форма по умолчанию 1280×760, минимальный размер 960×620.
- Пустой каталог показывает инструкцию добавления. Для каждой записи показываются состояния «Работает», «Остановлен» или «Исправить»; некорректные записи не скрываются.
- При добавлении название берётся из имени файла без расширения. В редакторе есть отдельные кнопки выбора файла и рабочей папки; название и рабочий каталог автоматически обновляются при смене файла, пока пользователь не изменил соответствующие поля вручную.
- Добавлен отдельный запускатель `Start-ScriptCatalog.ps1`. Он открывает только агрегатор пользовательских скриптов, использует отдельный mutex и не вызывает MainForm или четыре штатных worker-скрипта.
- Диалог добавления сначала предлагает `.ps1` и блокирует регистрацию интерпретаторов (`powershell.exe`, `pwsh.exe`, `cmd.exe`, `py.exe`, `python.exe`) вместо самих скриптов. Старые ошибочные записи остаются видимыми со статусом «Исправить» и не запускаются; их можно исправить через «Изменить» или удалить.
- Кнопка **«Импорт из текста»** открывает многострочный редактор: формат `Название | Путь | Режим | Аргументы` (последнее поле необязательно). Пути `@app\\файл.ps1` автоматически разрешаются относительно запущенной версии центра; поддерживаются абсолютные пути, относительные имена файлов и переменные среды `%LOCALAPPDATA%` / `%USERPROFILE%`. Кнопка «Проверить» показывает найденные файлы, дубли и ошибки; до успешной проверки импорт отключён. При ошибках импорт не сохраняет ничего. Готовый блок для вставки находится в `TEXT-IMPORT-FORTIS-RDG.txt`.
- Кнопка **«Готовый набор»** находит рядом с приложением пять Script Center adapter-файлов, создаёт именованные записи с абсолютными путями и стабильными bundle ID. Повторный импорт не создаёт дубликаты. Dependency preview теперь показывает resolver и файлы из соседнего Windows-клона `%USERPROFILE%\Repos\tunnel\runtime\windows-repo\current`, а также отдельные Windows-local runtime/state prerequisites. Он не читает содержимое ключей и не запускает процессы. При реальном запуске resolver проверяет оба чистых `main` клона, GitHub origins, синхронизацию с fetched `origin/main`, fingerprint manifest и восемь SHA-256. Полная таблица находится в `BUNDLE-MANIFEST.md`.
- `CI Watcher — запуск` и `CI Watcher — остановка` зарегистрированы как две отдельные одноразовые команды: запуск watcher не означает, что сам процесс watcher будет отображаться как долгоживущий локальный процесс в каталоге. Для остановки используется отдельная команда.
- Каталог проверяется на повреждённый XML; при ошибке приложение пытается загрузить последнюю рабочую резервную копию. Дублирующиеся/невалидные GUID записей исправляются в памяти; повторные одинаковые регистрации блокируются.
- Редактирование и удаление работающей записи запрещено, чтобы не потерять управление её процессом. Для остановки используется подтверждённое дерево PID, а не поиск по имени процесса.
- Script Center `Repo1-Worker.ps1` и `Repo2-Worker.ps1` теперь только делегируют соответствующим worker-файлам из tunnel mirror. Внутри tunnel mirror Repo2 worker публикует временный XML-маркер PID/start для существующего механизма наблюдения; Repo1 не требует маркера или запущенного Repo 2. Оба launcher-а сохраняют свои Guards/bootstrap checks. Это не означает, что холодный старт обоих Repo уже подтверждён.

## Не проверено

В Docker **нет Windows PowerShell 5.1, Windows Forms или C# компилятора**. Выполнены статические регрессионные и launcher-contract тесты командой `python3 -B test_static_catalog.py` и `python3 -B test_git_launcher_contract.py`; реальная WinForms-компиляция и интерактивная проверка регистрации/запуска/остановки остаются обязательными на Windows. Запуск C# GUI, `Script-Runner.ps1`, остановка дочерних процессов и сохранение каталога на настоящей Windows требуют проверки до установки в действующую среду. Не используйте пользовательские скрипты с секретами в аргументах: они сохраняются в открытом локальном файле.

**Важно:** режим «Своё окно» не перехватывает stdout/stderr. Режим «Внутри центра» собирает только текстовый stdout/stderr, не поддерживает stdin/TTY и не встраивает произвольные GUI-окна. Остановка завершает дерево процессов через `taskkill /T /F`, но не гарантирует завершение процессов, которые сами отсоединились, были переподчинены или запущены с повышенными правами. Существующие внешние сессии Fortis/RDG автоматически не присоединяются к этому механизму. Repo1 и Repo2 запускаются независимо; общий Docker/DC bootstrap по-прежнему контролируется исходными Guards.

## Безопасная последовательность на Windows

1. Создать **отдельную тестовую папку** из этой рабочей копии. Не копировать новую версию поверх работающего приложения.
2. Не останавливать и не перезапускать старый Control Center и четыре управляемых процесса. Сначала проверить компиляцию только агрегатора, **без запуска GUI**:

   `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Test-ScriptCatalogCompile.ps1`

3. Для проверки именно нового агрегатора (без главного окна с четырьмя штатными карточками) после переноса обновлённых файлов запустить `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start-ScriptCatalog.ps1`. У него отдельный mutex; он не запускает Repo 1/2, updater или watcher.
4. Для текущего Git-клонного режима не копировать worker-файлы вручную и не импортировать их повторно: пять записей уже указывают на стабильный Script Center clone. Сначала обновить оба соседних клона по `docs/GIT-WINDOWS-SOURCE-OF-TRUTH.md`; `Get-TunnelWindowsMirror.ps1` проверит правильный tunnel clone и его SHA-манифест перед запуском. Импорт остаётся только для новой установки; он не запускает скрипты и не меняет старые ошибочные записи `powershell.exe`.
5. Для первичной проверки использовать `Test-CatalogOnly.ps1`: он создаёт безопасный `safe-output.ps1` на 30 секунд и открывает только каталог. Проверить, что записи отображаются с именами файлов, журнал получает `SMOKE tick`, а «Остановить» завершает процесс. Затем закрыть и открыть каталог повторно, чтобы проверить сохранение. Старый `Start-ControlCenter.ps1` имеет собственный mutex; не обходить его для теста на боевом Windows.
6. Только после успешной приёмки отдельно согласовать установку. Старые исходники и рабочие журналы сохранять до проверки отката.

Никакие инструкции по реальному перезапуску Fortis Repo 1/2, updater или watcher не входят в этот кандидат.
