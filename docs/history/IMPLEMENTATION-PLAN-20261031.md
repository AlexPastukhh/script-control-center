# Fortis / RDG Control Center — модернизация существующего Windows-приложения

Статус: спецификация; исходники установленного Windows Control Center ещё не перенесены. Это НЕ новый проект и НЕ готовая реализация.

## Основной пользовательский сценарий

- В действующем Control Center выбрать «Добавить скрипт» и указать путь к уже существующему файлу.
- Автоматически распознать `.ps1`, `.cmd`, `.bat`, `.py` или `.exe`, предложить имя из имени файла.
- Не копировать и не изменять сам скрипт. Хранить в локальном профиле только ссылку на файл и настройки запуска.
- Необязательные поля: аргументы, рабочий каталог (по умолчанию каталог скрипта), способ запуска, источник логов.
- В одном интерфейсе видеть все записи, статус, время запуска, последние события, кнопки запуска и просмотра лога.
- Сохранять существующие 4 записи Fortis Repo 2 / Fortis Repo 1 / RDG updater / RDG CI watcher и их особенности.

## Режимы

1. **Скрытая консоль + лог в приложении** — для нового процесса, если поддерживается перенаправление stdout/stderr; собственное окно не создаётся.
2. **Обычное окно** — скрипт запускается штатно и может держать своё окно; Control Center следит за процессом, но не утверждает, что захватил вывод чужого окна.
3. **Подключённый внешний процесс** — обнаружен уже работающий процесс: без повторного запуска, только статус/проверка доступного файлового лога. Захват уже открытого stdout не обещать.

## Работа в фоне

- Закрытие/сворачивание GUI не должно завершать долгоживущий скрипт.
- Для скрытых скриптов вывод должен собираться независимым от GUI лёгким helper-процессом в локальные ограниченные по размеру log-файлы; UI читает их как viewer.
- При повторном открытии GUI восстановить статус и путь к файлу лога, не запускать второй экземпляр.
- Не завершать чужие процессы по совпадению имени. Для stop нужен подтверждённый PID/владение и отдельная политика завершения.
- Интерактивные stdin/tty-скрипты могут требовать обычного окна; скрытый захват stdout не равен встроенному терминалу.
- Установить лимит размера/срок хранения логов, маскировать секреты по возможности, показывать предупреждение о чувствительных данных.
- Запуск зарегистрированного скрипта — явное действие пользователя; никакого автоматического старта неизвестных скриптов при регистрации.

## Текущие ограничения и границы

- Repo 1 зависит от готовности Repo 2; RDG updater и watcher независимы.
- Не изменять RDG, FileQuarantine, рабочие Docker Volumes, контейнеры и живые сессии.
- Исходники текущего Fortis / RDG Control Center нужно сначала получить из Windows и проверить хеши; их нет в доступных исходниках Fortis Repo.
- Разработка и проверки исходников — внутри Fortis Repo, применение на Windows отдельно и явно.
- Не коммитить локальные абсолютные пути, токены, рабочие журналы и содержимое пользовательских скриптов.

## Приёмочные проверки

- Регистрация пути, повторное открытие UI, удаление записи без удаления скрипта.
- Путь не существует, права отказаны, некорректный интерпретатор, кавычки и пробелы в путях.
- Скрипт без окна, долгоживущий скрипт с выводом, краткая команда, скрипт с собственным окном.
- Дублирование процесса, выход с ошибкой, перезапуск UI, контроль памяти при длинном логе.
- Ранее запущенные Fortis Repo 1/2, updater и watcher остаются работающими при обновлении UI.
