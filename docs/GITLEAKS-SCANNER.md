# Gitleaks — локальный офлайн-сканер Script Catalog

**Owner:** `script-control-center`. **Статус:** SOURCE-VERIFIED для
проверяемого в Docker исходного кода; запуск GUI/CLI на Windows — **MANUAL-PENDING**.
Это не изменение запущенных Fortis, Docker, Tunnel или credentials.

## Компоненты и режимы

- `Start-GitleaksScanner.cmd` — единственная ручная запись Script Catalog
  (`window`, «Своё окно»). Запускает `Start-GitleaksScanner.ps1` через
  Windows PowerShell 5.1 `-NoProfile -STA -File` без `Execution Policy Bypass`.
  В самом Script Catalog обычные `.ps1` исторически запускаются с Bypass,
  поэтому **не регистрировать .ps1 напрямую** и не менять Execution Policy.
  Если локальная политика запрещает выполнение скрипта, запуск останавливается.
- `Start-GitleaksScanner.ps1` собирает `GitleaksScanEngine.cs` и
  `GitleaksScannerForm.cs` в памяти и открывает WinForms-окно.
  Engine запускает только установленный на хосте
  `%LOCALAPPDATA%\Tools\Gitleaks\v8.30.1\gitleaks.exe`.
  Загрузок/установок, внешних сервисов, сетевых Git-операций и изменения
  сканируемого проекта нет.
- `gitleaks dir` — текущие файлы, включая незакоммиченные.
  `gitleaks git` — история. Флажок «Вся доступная локальная история
  (--all)» использует стандартное для **8.30.1** поведение
  `git log --full-history --all`. Без флажка применяется
  `--log-opts="--full-history --diff-filter=tuxdb HEAD"` для текущей ветки.
  Не выполняется Git fetch: недоступные локально ветки и объекты не проверяются.
- Для истории нужны локальный `git.exe` и Git-репозиторий. Неправильные
  пути, отсутствие Gitleaks/Git и нераспознанные Git-репозитории дают ошибку.
  Проверка происходит в фоновой задаче, интерфейс не зависает.

## Регистрация и запуск

1. После приёма PR владелец обновляет Windows-клон
   `%USERPROFILE%\Repos\script-control-center` до принятого
   `main` согласно [Windows runbook](GIT-WINDOWS-SOURCE-OF-TRUTH.md).
   Docker task worktree — **не** Windows-клон.
2. В Script Catalog нажимает **«Импорт из текста»**, вставляет единственную
   рабочую строку из `TEXT-IMPORT-GITLEAKS.txt`:
   `Gitleaks — локальная проверка | @app\Start-GitleaksScanner.cmd | window`.
   Нажимает **«Проверить» → «Импортировать»**. Регистрация не запускает код.
3. Выбирает «Gitleaks — локальная проверка» и нажимает «▶ Запустить»,
   подтверждает старт. В GUI выбирает проект, `dir` или `git`,
   при желании всю доступную историю, и запускает проверку.
4. Видит прогресс, код завершения, количество находок, статус и путь к
   JSON. Кнопка «Открыть папку» открывает каталог отчёта, **не сам JSON**.

## Безопасность и результаты

Gitleaks запускается с `--redact=100 --no-banner --log-level=error`,
`--report-format=json --report-path` и отдельным `--exit-code=3`.
Интерпретация: **0 + пустой корректный JSON** → «Секреты не обнаружены»;
**3 + непустой корректный JSON** → число потенциальных находок;
любой другой код (включая **1**), несогласованность кода/JSON,
отсутствующий или повреждённый отчёт → **ошибка**, а не отсутствие секретов.

Stdout и stderr Gitleaks перехватываются и **никогда не пишутся в GUI,
консольные логи и чат**: там только собственные статусы, время и коды,
без выводимых значений или совпадений. JSON читается только для счёта
результатов, не отображается в UI.

Отчёты с находками сохраняются **локально, вне сканируемого репозитория**:
`%LOCALAPPDATA%\GitleaksReports\<UTC>-<GUID>\findings.json`.
Каждая отдельная папка создаётся с ограниченным ACL (текущий пользователь
и SYSTEM). Проверка отклоняет путь, при котором отчёты расположились
бы внутри выбранного проекта, и найденные reparse/junction-компоненты
путей. Пустой отчёт по успешному скану удаляется; после ошибки частичный
отчёт может сохраняться для диагностики.

Даже с маскировкой **отчёт может содержать конфиденциальные метаданные**:
пути, авторов, фрагменты исходников и сообщения коммитов. Не отправлять
его в чат, CI, облако или PR; изучать только локально, удалять после разбора.
Маскировка не гарантирует отсутствие иных конфиденциальных данных.
Закрытие GUI во время сканирования блокируется, чтобы избежать внезапно
оборванной проверки.

## Проверка на искусственных данных

Docker task worktree, без Fortis worker и изменений живых проектов:

```bash
python3 -B -m unittest test_gitleaks_scanner.py test_static_catalog.py test_mirror_browser_launcher.py test_qwen_mcp_launcher.py
```

Тест создаёт временный локальный Git-проект с **искусственным**
фиктивным маркером (не настоящим секретом): маркер есть в коммите, затем удалён
из текущего файла. Тестируется принцип различия `dir` и `git`.
При наличии Gitleaks отдельный CLI-тест проверяет чистый `dir`, находки
в истории, находки в текущих файлах и маскирование JSON. Если Gitleaks
недоступен, CLI-тест пропускается: не считать это успешным реальным запуском.

Исходник проверки: `tools/Test-GitleaksScannerCompile.ps1`.
Для Windows **после** source update выполнить compile-only preflight без
изменения PowerShell Execution Policy и без запуска сервисов:

```powershell
powershell.exe -NoProfile -STA -File .\tools\Test-GitleaksScannerCompile.ps1
```

Затем владелец проверяет GUI на отдельном одноразовом искусственном
проекте, ошибку отсутствующего бинарника/неверного пути и отсутствие
секретов в журналах. Пока реальный WinForms/Gitleaks 8.30.1 на Windows
не проверены, статус остаётся **MANUAL-PENDING**.

Проверяемые источники: `GitleaksScanEngine.cs`,
`GitleaksScannerForm.cs`, `test_gitleaks_scanner.py`.
